# AGENTS.md

Read the **Standards** in [README.md](README.md) before any change. They apply to agents and people alike, and they point to the guides and game docs that hold the details.

Each rule lives in one place: repo-wide standards in the README, operations in `docs/guides/`, and everything about one game in its folder, `docs/games/<slug>/` (its rules in `README.md`, its plans and its `history.md` beside it). Keep it that way; don't copy rules into this file.

Only for agents:

- Don't commit or push to `main` unless the user says to in the conversation.
- Right after cloning, run `git config remote.origin.fetch '+refs/heads/*:refs/remotes/origin/*'`. A shallow clone tracks only `main`, so pushes to a new branch aren't recorded locally and the end-of-turn git check wrongly reports them unpushed.
- Deliverables go in the repo, not zip files.
- One open pull request per conversation. Don't open a new one on top of the conversation's unmerged branch: until it's merged, add new work to it; once it's merged, start the next from an up-to-date `main`. (Squash merging breaks a stacked PR.) A conversation working on something else opens its own.
- Right after opening a pull request, edit its description once (re-send the same text). The cloud session adds a footer, a `---` line and "_Generated by Claude Code_", linking to the session; an edit puts the footer back with a plain `claude.ai/code` link instead, so the session link is gone. Only an edit on GitHub itself removes the footer entirely. `.claude/settings.json` turns off the other attribution, but not this.
